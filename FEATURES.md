# TaskSlash features

Checked against main at 8e5a020 on 2026-11-28.

## Command line
- `daemon-queue`: Run the daemon that holds the queue, decides when each submitted job starts and records each run; it runs until killed. How to reach it: `taskslash daemon`. Source: `crates/taskslash/src/main.rs:282`.
- `run-command`: Run a command as a job of the daemon, waiting until the daemon starts it, and exit with the command's own exit code (128+N when signal N killed it, 127 when it cannot be started, 1 when no daemon is running). How to reach it: `taskslash run -- <command>`. Source: `crates/taskslash/src/main.rs:176`.
- `run-options`: Give a job a name with `--name`, a cost kind with `--kind` (test, typecheck, build, browser or command), a priority class with `--class` (urgent, flake, interactive, normal or background), and its CPU in threads with `--cpu` and its memory in MiB with `--mem` in place of the learned estimate. How to reach it: `taskslash run --name <name> --kind <kind> --class <class> --cpu <threads> --mem <MiB> -- <command>`. Source: `crates/taskslash/src/main.rs:176`.
- `admission-by-capacity`: A job starts when its estimated CPU, memory and disk writes fit in what the machine has left, and waits while the machine's CPU, memory or I/O pressure is over a set line; only one job whose key never ran runs at a time, and when no other job runs, a job that has waited 3 minutes on CPU or I/O pressure or on room starts anyway. How to reach it: `taskslash run`, `taskslash moon`. Source: `crates/taskslash-core/src/admission.rs`, `crates/taskslash-core/src/order.rs`.
- `learned-estimates`: The daemon estimates what a key will cost from its recorded runs (memory from the worst recent run, CPU from a typical run taken while the machine was calm) and uses its kind's defaults for any figure no run feeds. How to reach it: `taskslash history <key>`. Source: `crates/taskslash-core/src/estimate.rs`.
- `priority-classes`: Waiting jobs are considered by priority class first, then the worktree using the smallest share of the machine, then time waited, and a scoped job runs with its class's CPU weight. How to reach it: `taskslash run --class <class>`. Source: `crates/taskslash-core/src/order.rs`, `crates/taskslash-core/src/launch.rs:75`.
- `measured-runs`: With a systemd user session, each job runs in its own systemd scope and the daemon records its wall time, CPU, peak memory, disk writes and exit code in a SQLite database; without one, the job runs as a plain child process and is not measured. How to reach it: `taskslash history <key>`. Source: `crates/taskslash-core/src/launch.rs`, `crates/taskslash-core/src/measure.rs`, `crates/taskslash-core/src/store.rs`.
- `moon-targets`: Run moon targets as one job per target, each once, after the targets it depends on have passed, ending with one line per target (pass, fail or skipped, wall time, cached, its key) and the command that prints a failed target's log; `--force` passes `--force` to every `moon run`, and `--class` sets the jobs' priority class. How to reach it: `taskslash moon <targets> --force --class <class>`. Source: `crates/taskslash/src/main.rs:214`.
- `history`: List every key with runs, or print one key's cost estimate and its newest runs with the worktree each ran in; `--limit` caps the runs shown (20 by default), `--where` keeps only the runs submitted from one worktree, and `--json` prints JSON. An unknown key exits 1 and names up to five keys like it. With no daemon running it reads the database read-only and says so on stderr. How to reach it: `taskslash history <key> --limit <n> --where <dir> --json`. Source: `crates/taskslash/src/main.rs:102`, `crates/taskslash-core/src/answers.rs`.
- `status`: Show the daemon's build, pid and uptime, the machine's load, pressure, memory and disks and the running and waiting jobs, from the daemon's latest readings; `--json` prints one line of JSON. How to reach it: `taskslash status --json`. Source: `crates/taskslash/src/main.rs:80`.
- `job-logs`: Print a job's or a run's log (its stdout and stderr together) after one line on stderr naming the run, key, worktree, exit code and start time: by job number, by run id with `--run`, the newest run of a key with `--last`, the newest failed run in this worktree with `--failed` (on the whole machine with `--all`), and follow a running job's log with `--follow` or `-f`; with no daemon running, `--run`, `--last` and `--failed` read the database read-only. How to reach it: `taskslash logs <job>`, `taskslash logs --run <id>`, `taskslash logs --last <key>`, `taskslash logs --failed <key> --all`, `taskslash logs <job> --follow`. Source: `crates/taskslash/src/main.rs:129`.
- `waiting-reason`: Say why a job waits, that it is running, or what run and exit code it ended with; with no job, list every waiting job and why; `--json` prints the reason as JSON. How to reach it: `taskslash why <job> --json`. Source: `crates/taskslash/src/main.rs:156`.
- `cancel`: Stop a waiting or running job from any terminal of the user who runs the daemon: a waiting job leaves the queue without running, and a running job's command gets SIGTERM, then SIGKILL after `--grace` seconds (10 by default, 0 sends SIGKILL at once). How to reach it: `taskslash cancel <job> --grace <seconds>`. Source: `crates/taskslash/src/main.rs:237`.
- `orphaned-command`: Stop the command of a job whose `taskslash run` or `taskslash moon` died before it ended: the daemon sends what is left of it (its scope, and the process group or tree the client reported) SIGTERM, then SIGKILL 10 seconds on, keeps the job counted until it is gone, and records the run with no exit code. How to reach it: automatic. Source: `crates/taskslash-core/src/daemon/orphan.rs`.
- `events`: Follow the daemon's job events (queued, started, finished, dropped) as one line of JSON each on stdout, as they happen, after a line on stderr saying it listens when stderr is a terminal. How to reach it: `taskslash events`. Source: `crates/taskslash/src/main.rs:267`.
- `top`: Show the machine's CPU, memory, pressure and load, the running and waiting jobs, the newest finished runs (from the database when it opens, then as jobs finish), and the selected job's log on one live terminal screen; up and down or j and k move the selection, enter opens the log in `$PAGER`, c pressed twice cancels the selected job, ? shows the keys, and q, Esc or Ctrl-C quit. How to reach it: `taskslash top`. Source: `crates/taskslash/src/main.rs:75`, `crates/taskslash/src/top.rs`.
- `version-help`: Print the version and the commit it was built from, or the help for taskslash (its commands by use, three examples and every setting) or any of its commands; bare `taskslash` prints the help and exits 0. How to reach it: `taskslash --version`, `taskslash`, `taskslash help`, `taskslash help <command>`. Source: `crates/taskslash/src/main.rs:33`, `crates/taskslash-core/build.rs`.
- `env-class`: Set the default priority class for `taskslash run` and `taskslash moon` when `--class` is not given; a value that is not a class is a usage error. How to reach it: `TASKSLASH_CLASS`. Source: `crates/taskslash/src/main.rs:295`.
- `env-logs`: Choose the directory job logs are kept in, how many days a finished job's log is kept (7 by default) and how many MiB the logs may take before the oldest are deleted (1024 by default). How to reach it: `TASKSLASH_LOGS`, `TASKSLASH_LOG_DAYS`, `TASKSLASH_LOG_MIB`. Source: `crates/taskslash-core/src/logs.rs`.
- `env-socket`: Choose the socket the daemon listens on and the commands talk to, in place of `$XDG_RUNTIME_DIR/taskslash/daemon.sock`. How to reach it: `TASKSLASH_SOCKET`. Source: `crates/taskslash-core/src/socket.rs`.
- `env-db`: Choose the SQLite database the daemon records runs in, in place of `$XDG_STATE_HOME/taskslash/taskslash.db`, or `~/.local/state/taskslash/taskslash.db` when `XDG_STATE_HOME` is not set. How to reach it: `TASKSLASH_DB`. Source: `crates/taskslash-core/src/store.rs`.
- `env-limits`: Change the share of CPU and memory and the disk write rate the daemon admits jobs against. How to reach it: `TASKSLASH_CPU_SHARE`, `TASKSLASH_MEM_SHARE`, `TASKSLASH_WRITE_MIB_S`. Source: `crates/taskslash-core/src/admission.rs`.
- `env-phases`: Make `taskslash run` say on stderr, when the job ends, how many milliseconds each start phase took (connect, admit, launch, command, drain, report), for the start benchmark. How to reach it: `TASKSLASH_PHASES=1`. Source: `crates/taskslash-core/src/phases.rs`.
- `no-web-app`: There is no web app and no HTTP API: every feature is reached through the `taskslash` command line and the daemon's socket. Source: `crates/taskslash/src/main.rs`.

## Plugins
- `command-plugins`: Run a program named `taskslash-<name>` on `PATH` as `taskslash <name>` when `<name>` is not a built-in command; the plugin gets `TASKSLASH_PROTOCOL`, `TASKSLASH_BIN` and, when the socket path resolves, `TASKSLASH_SOCKET` in its environment, and its exit code is taskslash's. How to reach it: `taskslash <name> [args...]`. Source: `crates/taskslash/src/main.rs:283`, `crates/taskslash-core/src/plugin.rs`.
- `plugins-list`: List every `taskslash-<name>` on `PATH` with the path that runs, marking later ones of the same name as shadowed and a name a built-in has as never run, or say there are none and what a plugin is named; `--json` prints one JSON array. How to reach it: `taskslash plugins --json`. Source: `crates/taskslash/src/main.rs:274`.

## Running as a service
- `install-service`: Build the binary from the repo with cargo, install it to `~/.cargo/bin/taskslash`, copy the user unit into the user's systemd directory, and enable it (or restart it on an upgrade), then wait for the daemon to answer. How to reach it: `bun scripts/install-service.ts`. Source: `scripts/install-service.ts`.
- `systemd-unit`: A systemd user unit, `taskslash.service`, runs `taskslash daemon` from `~/.cargo/bin`, restarts it on failure and starts it with the user session. How to reach it: `systemctl --user status taskslash`. Source: `crates/taskslash/systemd/taskslash.service`.

## Crates
- `taskslash-binary`: The `taskslash` binary is built and installed from source with cargo; there is no published release you can install yet. How to reach it: `cargo install --locked --path crates/taskslash`. Source: `crates/taskslash/Cargo.toml`, `scripts/install-service.ts:90`.
- `taskslash-core-internal`: `taskslash-core` holds the engine (the socket protocol, the daemon and the `run` client); it is internal and not installed by users. Source: `crates/taskslash-core/Cargo.toml`.
- `taskslash-floor-internal`: `taskslash-floor` is a bare pass-through and `floor-bench` a start benchmark that TaskSlash's own overhead is read against; both are internal and not installed by users. Source: `crates/taskslash-floor/Cargo.toml`, `crates/taskslash-floor/src/bin/floor-bench.rs`.
- `engine-package-internal`: The TypeScript package in `packages/engine` (`@hackcove/taskslash-engine`) is private; it is internal and not installed by users. Source: `packages/engine/package.json`.
